# Custom strategies

> **Languages:** English · [Português (BR)](./pt-BR/custom.md)

**Entry:** `webdimens/custom` · React / Vue / Svelte / Angular helpers in `webdimens/react`, `webdimens/vue`, `webdimens/svelte`, `webdimens/angular` · **[Full custom-strategy documentation](./custom/README.md)**

The 12 built-in strategies cover most sites. When an app (or a design system shared by several apps) needs its **own** growth law, this module lets you write it. It is the web port of the Android module `appdimens-dynamic-custom`. The simplest form is one line of typed TypeScript; the full form is a configuration that loads from JSON on every AppDimens platform (Android, KMP, iOS, Flutter, React Native, Web, Games, .NET) with the same numbers.

```ts
import { cdp, csp, customScaleStrategy, scalingFormula, defineScalingStrategy } from 'webdimens/custom';

// Factor: the number that multiplies every value
const product = customScaleStrategy(({ width, clamp }) => clamp(width / 360, 0.85, 1.8));
// Formula: the final value (base = the 16 in cdp(16, hud))
const hud = scalingFormula(({ base, sw, pow }) => base * pow(sw / 360, 0.8));
// Text, for JSON and remote config
const remote = scalingFormula('base * pow(sw / 360, 0.8)');
// Full configuration with rules
const brand = defineScalingStrategy({
  id: 'brand',
  reference: { width: 360, height: 640 },
  curve: { type: 'power', exponent: 0.8 },
  clamp: { min: 0.85, max: 1.6 },
  rules: [{ when: { device: ['tablet', 'desktop'] }, set: { curve: { type: 'logarithmic', k: 0.4 } } }],
});

cdp(16, product);          // CSS px
csp(18, hud);              // text, follows the user font scale
brand.css(16);             // "calc(16 * var(--cdp-brand))": responsive, no re-render, SSR-safe
```

```css
.card { padding: 8cdp-brand 16cdp-brand; font-size: 14csp-brand; }   /* PostCSS / dimens() */
```

## When to use it

- A design system shared by several apps that needs one growth law everywhere.
- A product whose UI must behave differently per device class or width range: TV, watch, tablet, desktop.
- Remote-config or A/B experiments on scaling, by shipping a new JSON.
- Built-ins that are close but need a different reference frame, exponent or bounds.

## Trade-offs

- Value-dependent strategies (`valueClamp`, code `scalingFormula`, `transform`, text formulas that are not `base * (…)`) cannot be one CSS variable: `css()` returns a px literal for the current viewport.
- Code functions cannot be exported to JSON; their text equivalents can.
- The aspect-ratio correction always uses the satellite law (`× (1 + k·ln(AR/1.78))`).

Parity: every platform runs the same fixture (`tests/fixtures/custom-strategy-fixture.json`, generated by the Kotlin reference engine). Factors, px and text sizes match within a relative tolerance of 1e-4.
